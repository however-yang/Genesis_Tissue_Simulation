完成了可独立启动的场景：65,688 个材料节点、正面居中略俯视相机、左侧水平夹爪、右侧 45° 剪刀，以及遮挡更少、反光更弱的脂肪床和暗红组织背景。**这是可试看的实验版本，交互无损验收未通过，未替换原默认版本。**

Linux 原生库 SHA-256：`8b24b3f7b6ec7f2d952437a2bf672a5d31604125ee881299450e3a4cca1691ec`；Windows 独立 DLL：`6c88979740445b09f94cc24a727d0458fc3fe3ff7bacf0fd85fed721fbf5fd99`。本轮不改原生求解器，也不改验收阈值。最终场景配置 SHA-256：`9087f679347fab329f9bb54a12ad42448767784d472540686d34cbc050475912`。

七组完整测试都在服务器第二张 A100 80 GB 上顺序运行，GPU UUID 为 `GPU-c1c4c0d5-5b39-9b0e-84a0-a667e65484fa`，有独占使用检查及 EGL 设备绑定。没有停止别人的任务、改网络或安装依赖。服务器其他 GPU/CPU 仍有科研任务，因此不是整机空载基准。测试完成后 GPU1 回到 0% / 14 MiB。

每组完成 1,110 个物理步；输出 1,280 × 960、每步一帧的完整无窗口录像。录像都解码到 1,110 帧、37 秒仿真时长。人工检查使用阶段原图及按仿真时间每秒抽样图板，不能称为逐帧或临床真实性验证。主要视觉对照为基线、仅减节点版本与最终版本。

## 实测性能

原生步是 `LCS_Step` 调用墙钟耗时；“含渲染录像”包含步进、读回、表面处理、检查提交和同步 RGB 渲染/视频写入，不包含阶段截图存储与最终异步检查清空。两项均不是 Windows 异步窗口显示 FPS，也不是完整 RL RGB-D 流水线速度。

| 测试 | 材料节点 | 原生步均值 ms | 原生步折合 Hz | 含渲染录像均值 ms | 含渲染录像 Hz |
|---|---:|---:|---:|---:|---:|
| baseline-r1，原布局 | 102,710 | 41.84 | 23.90 | 122.41 | 8.17 |
| baseline-r2，原布局复测 | 102,710 | 41.79 | 23.93 | 123.43 | 8.10 |
| mesh65-r1，只减节点 | 65,688 | 33.43 | 29.91 | 101.10 | 9.89 |
| frontal65-r2，左上夹爪 | 65,688 | 33.07 | 30.24 | 100.07 | 9.99 |
| frontal65-r3，水平左夹爪 | 65,688 | 33.27 | 30.05 | 96.41 | 10.37 |
| frontal68-r4，68k 对照，未采用 | 68,516 | 33.86 | 29.53 | 104.95 | 9.53 |
| **frontal65-r5，最终镜头** | **65,688** | **33.37** | **29.97** | **108.13** | **9.25** |

最终版原生步比两次基线约少 20% 时间，但没有达到 33 Hz。最终版原生步 p95 为 40.46 ms；含渲染录像 p95 为 156.61 ms，不能保证最低帧率。

最终版均值拆分：原生步 33.37 ms；连同状态读回 38.17 ms；渲染及视频写入 67.70 ms；其他表面处理/提交等约 2.26 ms。渲染及写视频约占当前测量帧耗时的 63%，所以只减物理节点不能使完整画面达到 33 Hz。本轮没有进一步区分渲染和编码，也没有拆分材料/接触内核，不能将这两个聚合值误称为特定内核耗时。

Windows RTX 3090 被已有训练持续占用，本轮只做了本机 CPU 配置检查与 DLL 哈希核对，没有启动与它争抢资源的 GPU 仿真。因此 **Windows 新场景显示 FPS 尚未测得**。窗口运行时应查看终端各阶段的 `display ... fps`，不能从 A100 数据换算。

全部完整运行都完成了抓取、牵拉、两次剪切、撤刀与提离，没有记录到抓持后丢失、撤刀新增切边、未切列或肿瘤材料残留。已保存阶段的表面检查没有退化三角形、开放边、非流形边、重复三角形，绕序一致。由于 `hold` 最终验收抛出异常，表面阶段审计不含 `hold`；不能把此前阶段检查当成最终拓扑通过。

必须保留以下三项问题：

1. **表皮误切仍未清零。** 原基线也失败，但新版本仍有 12–23 条，不能因为比旧值少就判定通过；不同网格的边计数也不完全可比。
2. **最终复测出现格点层残连。** `material_components=2`，但 `lattice_pieces=1`，违反原有“两个计数都必须为 2”的验收。画面能看见提离块与肾脏间的空隙，也不能排除经非材料格点仍有连接。不得宣称已经解决藕断丝连。
3. **反力尖峰和重复性未解决。** 仅减节点版本达 41.10 N，水平夹爪版本一次 42.14 N，68,516 节点版本达 97.19 N。最终复测峰值虽回落到 6.22 N，也不能用单次较好值消除前面的风险。r3 与 r5 物理布局相同，仅相机不同，却有切边与连通性结果波动，原因未定位，不能归因于相机或认定物理一致。

上述验收失败均保留 `status=failed`、原始异常和非零退出码。反力峰值不是当前最终门槛的一部分，仍作为额外风险记录。完整逐条条件复算与各阶段耗时在 [summary.json](review/summary.json)。

切割前的单次形变比较使用 baseline-r1 与 mesh65-r1 的 `lift.npz`，将粗网格位移插值到远离边界的共同内部点：76,274 点位移 RMS 差约 **0.169 mm**；肿瘤颈部 892 点约 **0.554 mm**，最大约 **1.262 mm**。该差值包含离散/插值误差，仅覆盖原器械姿态、切割前的一帧，不证明新布局或切割后的物理等价。细节见 [precut-deformation-comparison.json](review/precut-deformation-comparison.json)。

本场景沿用 `contact_model=2` 辅助夹持；没有完成用户最终要求的纯摩擦夹持真实性验证，也没有本轮标定组织材料。

## 使用和后续顺序

启动命令见 [README.md](README.md)。原默认入口、原 DLL 和主工作区现有修改均未覆盖；所有新代码、录像与记录位于这个独立目录。未向 GitHub 推送本轮实验。

下一步应先定位粗网格的非材料格点残连及接触峰值/重复性，在原验收阈值下通过多次完整夹取切割对照，再考虑替换默认场景。之后应在 GPU 空闲时测 Windows 显示路径，并分别测量渲染、视频写入和 CPU/GPU 读回，决定后续实时性优化方向。当前证据不支持“无损替换”或“稳定 33 Hz”的结论。
