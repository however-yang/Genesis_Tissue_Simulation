# S18–S25 实施与验收记录

日期：2026-11-03。候选位于本目录 `source/`；正式发布目录、默认入口、默认原生库未替换。**当前不是可上线版本：完整渲染帧尚未达到 20 Hz，S18/S22 的物理验收尚未通过。** 所有失败保留。本文区分实现、实测与未验证范围。

## 用户确认的验收定义

- 20 Hz 以单环境完整交互帧计，包含物理、接触/切割、质量检查和渲染；并行吞吐量不能替代。
- S25 使用像素的支撑材料节点 ID 与插值权重。原生切面绑定有仿射偏移，必须一并导出；不能伪造唯一最近节点。
- 不减少物理子步、不放宽阈值、不跳过质量检查、不以重复画面充当新物理帧。没有修改材料/接触/切割规则来制造耦合。
- 本轮不升级依赖，不修改网络，不中断其他用户任务。只使用显式检查空闲的 GPU 1；系统 GDM 显示进程单独记录，其他图形和计算进程仍阻止准入。

## 架构与代码位置

```text
策略 → tool_kinematics_v1 → worker/NativeEnvironment → 原有 CUDA 物理步
                                         ↓
                           原始质量证据 + 结果分类/事件
                                         ↓
                     策略观测          特权状态/视觉标签
                         ↓                    ↓
                       learner           EpisodeWriter

控制面：ParallelNativePool(reset/step/snapshot/restore/drop)
作业面：server_queue → 固定源码/spec/库 → 资源守卫 → 独立 experiment 子进程
```

- `training/outcomes.py`、`env.py`、`tasks.py`、`data.py`、`experiment.py`：终止和数据语义。数值失败优先，材料分离须有当步原因支持；滑脱/失抓事件本身不终止。
- `training/policies.py`：部署白名单。`previous_target_si` 来自限速后动作，不采用受载后求解位置，也不采用反馈修正后的驱动目标。求解位置/所有力及遥测保留在特权通道。
- `training/pool_session.py`、`parallel.py`、`prepared_snapshot.py`、`snapshot.py`：预算、归属和谱系。单快照原生数据约 1.258 GB，捕获临时内存与压缩/热缓存分别限额；池内同时只允许一个内存操作。
- `training/instrument_collision.py`：钳口和刀身采用完整网格的包络盒，腕部沿用原生胶囊。报告标明几何定义，不能把包络穿入一概解释为真实 CAD 穿透。
- `training/egl_device.py`、`resources.py`：EGL 与 CUDA 按 GPU UUID 绑定；同时监视图形/计算上下文。`CUDA_VISIBLE_DEVICES` 本身不保证 EGL 选择同一块卡。
- `training/topology_fast.py`、`topology_hash.py`：opt-in 的等价 CPU 哈希计数。保持同样顶点舍入、面积/边/重复面/绕向规则，不跨帧缓存，也不降低检查频率；超出键容量回退原算法。
- `training/vision.py`、`visual_randomization.py`、`visual_labels.py`、`pixel_labels.py`：同步视觉与特权标签，新增浮点 OpenGL 可见三角形/透视插值通道；不改正式渲染器的着色器。
- `native-s25/source/vendor/cuda/xpbd/labels_readback.cuh`：复用原生表面绑定核，在临时缓冲区计算当前绑定。临时分配不进入持久快照分配追踪。仅此新文件及翻译单元末尾 include 与 R3 不同，物理核未变。

所有功能显式启用，详见 `README.md`。可迁移的原生覆盖文件保存在 `source/parallel_simulation_tests/20261103-s18-s25-candidate/native-overlay/`，基于仓库内 R3 源码。原生标签 ABI 为 2，快照 ABI 仍为 1；具体文件哈希见 `native-s25/manifest.json`。

## 已验证的 S25 标签定义与精度

组织像素重建：

`x_pixel(m) = sum_slot(weight[slot] * node_position_m[node_id[slot]]) + offset_m`

每像素最多 24 槽（3 个表面顶点，各最多 8 个支撑），允许同一节点重复，按槽求和。无效像素 ID=-1、权重=0，并有有效性掩码。偏移来自原生接触仿射模型，尤其切面上不能省略；这不是精确的全局 FEM 形函数。

真实起切且随机化后的结果：

- 表面有效支撑 45,288 / 45,288；可见组织像素有效 27,720 / 27,721。
- 分割与独立三角形通道的组织可见性不一致数为 0。
- 最大重投影误差 0.002604 px；与独立像素中心深度的最大偏差 1.088 µm。
- 五次恢复位置最大差为 0，原生档案逐字节相等；标签提取前后原生档案也相等。
- 同状态重复噪声图像差为 0，随机种子/原生 tick 确定噪声，不靠全局 RNG 的偶然调用顺序。
- RGB-D 传感图沿用现有多重采样解析，并可有噪声；标签是像素中心真值。轮廓处两种深度定义不相同，单独导出中心深度及传感器差值，不能拿噪声/MSAA 深度直接要求逐像素相等。
- 320×240 的一次暖态完整视觉/稠密标签采集为 **116.87 ms**，不满足实时门槛。

证据：`results/diagnostics-01/s25-cut-randomized/attempt-000/probe/result.json`；该目录保留 RGB、分割、有效性图和表面状态。早期 ABI v1 只读缓存几乎全部失效，早期 v2 临时分配推进快照序号，均已保留并修复，不能混用旧结果作为通过证据。

## 完整帧性能

以下均为 wall-traction 完整名义轨迹 1410 帧、1280×960、supersample=1、每物理步新 RGB-D、完整现有质量检查、OpenCV 4 线程，EGL/CUDA 同为 GPU 1。初始化/JIT 不计帧；资源监控为独立线程。不是并行吞吐量，也没有计入远程显示/编码/传输延迟。

| 版本 | 平均有效帧率 | 平均帧 ms | P95 ms | 最慢 20 帧窗口 Hz | >50 ms 帧 | 步内质量检查 |
|---|---:|---:|---:|---:|---:|---|
| 原版适配器/默认库 | 6.34 | 157.74 | 300.84 | 3.15 | 1410/1410 | 通过 |
| 候选 S19/S22 + 等价拓扑检查 | 11.60 | 86.18 | 123.43 | 7.77 | 1410/1410 | 通过 |

这两次不是 ABBA 重复；共享服务器 CPU 负载明显波动，不能据此承诺固定倍数提升，也不能据此推断用户当前 GUI 就是这个帧率。默认渲染 supersample=2 尚未测；这里甚至在较低渲染成本配置下也没达到 20 Hz。**没有“保持 20 Hz”的合格结论，不能正式集成。**

| 候选暖态成本 | 平均 ms |
|---|---:|
| 原生步（包含接触/形变/切割，未分开测） | 32.48 |
| 质量检查及表面导出 | 19.68 |
| Python 状态快照（不是完整原生分支快照） | 3.22 |
| 更新场景并渲染 RGB-D | 30.17 |

候选采样中显存峰值 2043 MiB、GPU 利用率均值 29.49%/峰值 56%；包含初始化和系统显示上下文，不等于纯物理利用率。CPU 全机采样均值约 49%、峰值约 86%。单环境首先受串行步骤、CPU 几何处理、绘制/读回及调度影响，而不是 80 GB 显存容量不足。没有内核级计时，不把原生 32.48 ms 虚构拆成接触/切割各多少。

真实表面检查的独立 CPU 微基准中，等价实现从 70.79 ms 降至 5.12 ms；64 组正常/破坏拓扑对照输出一致，完整名义轨迹也保留每步检查。该微基准只说明拓扑诊断成本，不代表完整帧能达到 20 Hz。

原始性能及资源文件：`results/interactive-baseline-cv4-01/`、`results/interactive-fast-cv4-01/`；汇总 CSV/JSON：`results/performance-summary.*`；拒绝上线结果：`results/adoption-gate.json`。早期 EGL 默认 GPU0、CUDA GPU1 的运行只保留诊断，不用于单卡性能验收。

## 推荐实施顺序

1. **先守住正式版本。** 当前候选保持隔离；不改变原有交互入口。没有满足完整帧门槛和人工交互回归之前，不合入默认版本。
2. **把性能瓶颈进一步定位到函数/内核。** 在同分辨率、同抗锯齿和可比较 CPU 负载下做配对计时；优先优化 CPU 几何/渲染重复工作、批量读回和内核启动。显存够用不能直接解决延迟；标签默认留在训练 worker 的数据文件，避免稠密数组逐步 IPC。
3. **修 S18 的几何准备与轨迹。** 根部支撑缩小会使组织沉降，固定休止位置抓取会落空；自适应准备需要检查材料见证点、抓持和刀身间隙。两接触模型和三剪名义回归先通过，再做 C1/C2/C4/C5，失败场景不批量堆 200 次无效样本。
4. **处理 S22 的真实名义冲突。** 先用精确工具表面/原生腕部包络定位；需要绕行时在独立训练轨迹中改进并重新验证组织交互。不得减小器械碰撞体或放宽 0.2 mm 来让测试通过。
5. **完成 S19 原生撕裂分离正对照。** 当前 tear=2 的名义轨迹及 +y/-z 两个方向各 4 mm、90 步平滑牵拉加 30 步保持均未触发撕裂/材料分离，不足以证明终止路径。沿用已标定 S16 方案；不能为了触发标签随意降低撕裂阈值。
6. **训练接线先用小池。** 服务器队列绑定候选 SHA；S20 先 2/4 worker，数据在 worker 本地，按 episode/branch/seed/config 分组，策略不读取特权标签。只有既有 32 环境全部稳定后才放开 16 上限。
7. **最后考虑朝向扩展。** 先按 `S24_ASSESSMENT.md` 验证抓持与快照，再增加版本化动作合同和经实测确定的限速。S18 如果固定朝向足够，可继续推迟。
