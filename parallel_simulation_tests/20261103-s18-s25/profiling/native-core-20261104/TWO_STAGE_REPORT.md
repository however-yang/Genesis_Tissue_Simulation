# 原生物理、接触与切割性能专项：实测与交付

此文件归档剪刀合批加材料缓存的已完成数据。最终结论见 REPORT.md。

**稳定20Hz尚未通过。** 已验证候选在两轮完整1410帧 RGB-D 中达到 **22.64 / 22.58 Hz**，P95 **51.13 / 51.61 ms**。最慢20帧窗口 **17.97 Hz**。正式入口未替换，物理域与训练域仍未批准。

## 到底哪里最耗时

以下为两轮合并数据（每种配置2820帧），单位是每个完整交互帧的 wall-clock ms。质量行包含表面导出，不能再加一次 surface_export。State 构造不是每帧保存完整原生快照。

|不重复阶段|原核 ms|候选 ms|候选占比|
|---|---:|---:|---:|
|原生物理、接触、切割及同步观测|31.369|29.051|65.7%|
|质量检查与表面导出|4.265|4.271|9.7%|
|State 构造|1.314|1.304|2.9%|
|当前帧完整 RGB-D、深度对齐及CPU返回|8.277|8.297|18.8%|
|控制、策略观测复制等|1.313|1.304|2.9%|

原核阶段占原完整帧 **67.4%**，是主要瓶颈。多数物理主计算本来就在CUDA中；本轮收益来自GPU内部的查询调度和重复材料计算消除。



## GPU真正执行的热点

下表是同一切割窗口470–481的12帧 Nsight 节点级捕获。它含插桩开销，与整段1410帧平均FPS分开。接触、材料和控制在统一目标中耦合，不能把所有“材料核”当成与接触完全无关的独立物理阶段。

|CUDA工作|原核 ms/帧|候选 ms/帧|
|---|---:|---:|
|接触查询及保持器械分组的追加|10.101|5.520|
|粗尺度材料累加|3.643|3.837|
|材料步长界限|1.623|0.386|
|接触/抓取装配|2.368|2.402|
|局部顶点求解|1.712|1.731|
|接触面采样|1.697|1.725|
|最小体积修复|0.913|0.924|

原162次/帧查询中，135次是剪刀、27次是抓钳。本候选将剪刀的同轮形状放入二维网格，每轮保留原查询、各自结果列表和原器械分组次序；查询核54次及分组追加27次替代原162次查询核。抓钳暂保持原分派，另有独立扩展试验。

材料步长界限从 **1.623→0.386ms**，累加因写入缓存从 **3.643→3.837ms**；两者合计仍净省约 **1.045ms/切割帧**。GPU核区间并集从 **36.570→31.195ms**。这些是实测窗口数据，不是理论峰值估算。

切断和重建的代表核本身较小：候选窗口内 `k_CutScissorsLevels` 0.017ms、`k_BuildCutTriangles` 0.039ms、`k_BindSurface` 0.044ms。它们不是全部切割成本；切割引发的接触重绑、体积修复与继续求解已体现在查询/材料/修复核中，不得漏算或重复算。

两轮合并：**21.49→22.61Hz**，平均 **46.539→44.228ms**，速度比 **1.052×**。P95 **56.678→51.424ms**，仍超过50ms；最慢20帧窗口未守住20Hz。

含原检查、State和控制的无图测试：**26.92→28.68Hz**。它不同于原生阶段倒数，也不同于完整RGB-D FPS。

NVML测量时段GPU利用率均值 **71.0%→69.7%**，显存采样峰值 **2120→2136MiB**。GPU工作减少后利用率不必升高。主机CPU全机均值约1.17%/1.14%，该数值不能代替主线程分析。

每帧都执行原物理、接触、切割、质量检查和新RGB-D，返回原始深度、RGB对齐深度、有效性与独立CPU观测。未降低1280×960、原3子步、8次接触细化、材料/摩擦/切割参数或精度。显示刷新、网络、录像写盘、策略网络推理和训练不在此基准中；密集S25逐像素支撑ID/权重未启用，不能据本表声称它已达20Hz。

每个完整测试固定1410步、seed 0、settled/wall-traction；CPU亲和7,19,20,25，BLAS/OMP与OpenCV各1线程。仅用UUID `GPU-c1c4c0d5-5b39-9b0e-84a0-a667e65484fa` 的A100 80GB。最后ABBA期间没有本助手并发编译；其余GPU任务未动，未改时钟、MPS、MIG、系统权限或网络。初始化/重置与首轮图像预热不计稳态帧时间，运行中的新拓扑与新几何开销保留。历史11.60Hz与本轮负载时段不同，不作为本轮代码收益的分母。



## 保留的代码改动

1. **剪刀同轮形状查询合批**：保留原 `k_FindSurface`，新增同数学体的二维核；每种形状独立活动表，再按原形状顺序拼接。完整有效接触字节、节点度数、活动ID多重集合和跨形状次序逐项对照。三角形超容量、无耦合body或额外不支持的流使用原实现。
2. **同一粗尺度方向的材料系数复用**：累加时缓存本来已计算的四面体体积J和方向梯度gJ，随后步长界限读取；两者之间只累加块能量和求块步长，不改节点位置/权重/活性/组件。每次累加覆盖整个四面体池，包括死单元的空标记；不跨方向、迭代、子步、帧或拓扑更新复用旧值。

正常GPU新增缓存约10MB，使用私有原始CUDA分配，不进入物理快照字段；所有旧物理字段保留。诊断开关才输出生产核的真实梯度/Hessian/界限，由独立GPU核与原公式比较；生产与诊断使用同一已编译生产核，不用另一份调试实现替代它。

代码位置：[查询核和对照](native-bound-cache/source/vendor/cuda/contact/surface_contact.cuh)、[剪刀分派](native-bound-cache/source/vendor/cuda/cutting/pressure_blade.cuh)、[材料系数缓存](native-bound-cache/source/vendor/cuda/contact/coarse_bound_cache.cuh)、[六处累加/界限依赖链](native-bound-cache/source/vendor/cuda/xpbd/xpbd_solver.cu)、[接触面采样对照](native-bound-cache/source/vendor/cuda/contact/manifold_validation.cuh)。原参考313个设备函数SASS逐指令一致，见 [证明](results/bound-cache-device-binding.json)。

启动配置为 query_mode=1、query_threads=64、assembly_blocks=512、manifold_blocks=1024、bound_cache=true。参数仅可在原生初始化前设置；跨进程采样和快照复现必须记录DLL散列、执行配置与源码散列，不能只记录材料参数。正式默认入口未修改。

## 正确性与不能掩盖的失败

完整1410帧的生产核对照包含材料累加 **10,446,819,600** 项和步长界限 **10,446,819,600** 项，目标块、梯度/Hessian和界限尺度差异均0；其中受限于0–1之间的非平凡界限 **138,368** 个。该轮接触有效记录 **1,047,812**、接触面记录 **7,709,451**，所有字节/权重/度数/集合/次序差异0，覆盖CUDA Graph，未跳过分支。详见 [完整验证](results/bound-cache-full-validation/result-summary.json)。

最终两轮RGB-D和无图完整脚本的原检查通过；32步真实闭合切割触发cut_onset，4个当前状态RGB逐位一致，深度误差≤1e-6m、有效性一致，旧观测不被后帧覆盖。完整原生快照可逐位恢复，恢复后下一步检查通过，重复拓扑诊断不改物理快照。证据：[图像回归](results/delivery-current-frame/result.json)、[快照回归](results/delivery-snapshot-roundtrip/result.json)、[真实切割图像](results/delivery-current-frame/current-rgb-step-31.png)。

这不证明未来轨迹逐位确定。原实现已有浮点原子累加次序不确定性；同输入接触装配A/A与调度A/B最大相对系数差异约1e-7，不能据此批准整个物理域。

|已实施但排除的方案|实测结果|处置|
|---|---|---|
|较小装配/采样网格及128线程查询组合|局部最快约22.5Hz；最终完整验证在第三刀触发一条位置非流形边|排除调度组合，保留原512/1024网格及64线程|
|256/256网格|第三刀第1094帧位置非流形边=1|失败，CPU复核一致|
|严格零贡献快捷路径|5927万项对照差异0；完整44.823→45.672ms|无收益，排除|
|只压紧已有宽相位组|接触局部对照通过；RGB-D第二刀第793帧非流形边=1|失败，排除|
|原三角形包围盒预过滤|完整对照通过；44.981→45.740ms|无收益，排除|

失败与调度变更的因果关系尚未建立，当前均按失败处理，不用“原来就不稳定”覆盖它们，也不放宽检查。失败帧与快照保留；见 [CPU复核](results/rejected-physical-runs.json)。

原S18–S25中已有的新几何重复不稳定、纯摩擦准备失败、wall器械碰撞失败、真实撕裂分离正对照未触发、连续S25绑定错位、随机化可见性与未来轨迹不确定性均未被本轮修复。`formal_physics_domain_approved=false`、`training_domain_approved=false`。参考 [原报告](../../REPORT.md) 和 [上一轮报告](../aggressive-20261104/REPORT.md)。

## 剩余瓶颈与实施顺序

当前主要剩余预算仍在接触窄相位和材料累加：查询约5.5ms、粗尺度累加约3.8ms/高负载切割帧；RGB-D路径约8.3ms/整段平均帧也保留。若继续追求稳定20Hz，优先对查询核的几何距离、缓存查找和24节点见证构造做子阶段测量，再验证warp协作/数据布局原型；其次评估接触装配与顶点求解的数据流融合。收益尚未测得，不能写成已实现。现有双路径GPU对照可用于限制下一步改造。

图生命周期和中间读回也可分析，但API长包络大多与GPU工作重叠，不能把整段等待当成可直接删除的预算。现有CUDA Graph已经启用。继续减少求解次数、降低图像分辨率或使用上一帧状态不在本方案中。

本轮只测单环境关键路径，未对新版多worker吞吐或并发训练作验收；不能将单环境Hz乘以worker数。后续采样须将失败轨迹隔离，记录env/episode/tick、执行配置与二进制/源码散列；两张A100可以分配独立采样与学习任务，但当前测试不证明该分配下的实时性。
