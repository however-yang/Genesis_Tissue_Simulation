# 实验取舍与不可改变的约束

所有候选均处于独立目录，推荐开关最终以 REPORT.md 和最终复测为准；保留失败实验仅用于审计，不意味着继续启用。

## 测量口径

- 同一 A100 UUID，CPU 亲和性 7、19、20、25，BLAS/OMP 单线程；仅 OpenCV 线程数作为显式实验变量。
- 同一 wall-traction、settled、seed=0、1410 步动作，1280×960，MSAA/灯光/相机保持原值，每一步完成物理、全部已启用检查、新 RGB-D 和策略观测复制。
- RGB、原始针孔深度、畸变对齐深度及有效性返回 CPU；包含 native、GL 的读回。远程桌面、网络传输、显示刷新和磁盘录像不在此口径内；这些额外成本不能凭此声称满足 20 Hz。
- 原 dt=1/30 s、3 子步、8 次接触细化，以及原材料、切割、接触模型和质量阈值均不变。更改 dt、丢弃慢帧、复用旧图或降低精度均不能作为优化成绩。
- 密集 S25 支撑节点/权重标签不是原 11.60 Hz RGB-D 基准启用项，因此单独分析，不能把无密集标签的成绩描述成全标签达标。
- 不将 cProfile / Nsight 窗口、CPU/GPU 逐帧双算对照或不完整场景的 FPS 列作验收成绩。
- 每个库、Python 源码及命令保留散列和日志。GPU 守卫遇到外来进程退出本轮测试，不终止外来任务；已发生的资源中断保留在原目录。

## 为什么不是把全部 Python 都搬到 CUDA

每帧网格属性融合后约0.63 ms，精确距离和双夹爪测试各约毫秒级。它们在 CPU 上处理已回传的表面/状态，不值得凭猜测新增 GPU 往返。GPU 拓扑摘要实验则针对多毫秒的全表面整数处理，已有独立 GPU 实现与完整标准对照。物理主数组原本就在 CUDA 设备上；增加 GPU 利用率本身不是目标，必须实际减少同帧端到端 wall-clock。

## 物理验收边界

质量检查通过仅表示该固定脚本在既有局部检查范围内通过。原有新几何重复不稳定、纯摩擦准备失败、wall 仪器碰撞失败、真实撕裂分离正对照未触发、连续 S25 支撑绑定错位、随机化可见性失败及 A/A 未来轨迹不确定性仍未解除。所有最终输出继续标记 `formal_physics_domain_approved=False`。不得把失败实验或更高 FPS 当作这些问题已经修复。

私有缓冲快照问题已单独定位并修复：初版只有5个新增拓扑派生缓冲改变，旧物理字段不变；修正版不把新临时工作区纳入物理快照，不改原快照实现/ABI，并通过完整快照/恢复和1410帧双算。最终物理核308个均与原库SASS一致。形状预计算虽960次零差异，但完整ABBA无收益，未保留。
