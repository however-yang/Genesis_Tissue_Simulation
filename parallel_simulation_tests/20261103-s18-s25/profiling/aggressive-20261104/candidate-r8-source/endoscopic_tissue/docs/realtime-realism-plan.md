# 实时与真实感兼顾：实施计划

> 执行方式：三个子代理并行实施（用户要求），主会话负责分工、合并、最终验证与测量。每个子代理只改自己名下的文件，见“文件归属”。

**目标：** 薄壁剪刀场景（`--scene wall-traction`，`--scene wall`）在实时窗口里按真实速度流畅播放脚本流程（每步模拟 1/30 s，每步总耗时不超过 33 ms），同时不降低剪切、夹持和画面的真实感：保持 1 mm 网格、整块组织参与计算、双刃挤压起切规则和现有全部验收线。

**架构：** 物理在工作线程中按墙钟节拍推进（ctypes 调用原生库期间释放 GIL），渲染在主线程用最新快照出图，两者并行。物理侧靠算法与实现优化降到预算内；渲染侧去掉无效计算并提升内窥镜画面质感；夹钳由锚点辅助夹持改为摩擦夹持。

**技术栈：** Python 3（numpy、ctypes、OpenCV、Genesis/pyrender 光栅化），CUDA 12.5 原生库（VS 2022 / NMake 构建），RTX 3090。

## 全局约束

- 用户确定的“实时”：脚本流程按真实速度播放，不做交互输入。
- 实时优先，但不得用降低真实感换速度：不缩小参与计算的组织块，不改粗网格（保持 1 mm），不改剪切/夹持的物理规则来换时间。超预算时报告差距，由用户决定。
- 剪刀起切规则不得放宽：两刃各自达到起切力一半并挤压 2 mm 后才能剪开（见记忆 scissors-fracture-rule）。
- 现有验收线不得放宽：非刃口重叠 0.2 mm、断边只在剪切面一层、退刀不新增断边、剪后连通、表面拓扑、验收区间全部剪断等。
- 默认 DLL `native/bin-scissors/LiverCudaSim.dll`（`29d9f329…`）在合并前不得覆盖；原 `native/bin/` 永不覆盖。
- 原生库输出目录：阶段二用 `native/bin-realtime/`；只有阶段二构建原生库。
- 代码风格：沿用周边代码；源码只用 ASCII；不用 getattr/hasattr；不写宽泛 except；注释说明“为什么”；不留死代码；测试放在 `test_core.py`，测试函数不写 docstring。
- Python：`D:\develop\anaconda3\envs\genesis_world\python.exe`，在 `D:\Simulation\genesis-world` 下运行，`PYTHONPATH=.`。原生库每次运行都有随机性：任何结论至少 2–3 次运行。
- GPU 共享协议（见下文）：计时测量必须独占 GPU，验收运行可以共享。

## 基线测量（2026-10-28，RTX 3090）

| 项目 | 现在 |
|---|---|
| 物理（3 子步）| 空闲 65 ms/步，夹持/剪切 100–110 ms/步 |
| 物理（1 子步，单次通过验收）| `LCS_Step` 空闲 20 / 夹持 27 / 剪切 32–33 ms；接触曲面修复 空闲 0.2 / 夹持后 12.4–13.6 ms；Finalize 0.5 ms |
| 每步 Python | 刀背重叠质检 15 ms，读回 1.5 ms，记录约 2 ms |
| 每帧渲染 | 网格重建 107 ms（细分 16 倍，像素级无差别），出图 135 ms（2 倍超采样 + CPU 缩放 + 每帧重算暗角；GPU 本身 15–30 ms） |

预算目标（剪切阶段中位数）：原生物理 ≤ 25 ms/步，每步 Python ≤ 4 ms，渲染在主线程并行 ≤ 30 ms/帧。

## GPU 共享协议

锁目录：`C:\WINDOWS\TEMP\claude\D--Simulation-genesis-world\6de6da1d-3b43-4fa3-91f1-fd2ef998be2d\scratchpad\gpu-locks\`

- 计时测量（需要准确的毫秒数）：先 `mkdir gpu-locks/exclusive`（创建成功才算拿到锁；失败就每 30 s 重试），再等到 `gpu-locks/` 下没有 `shared-*` 目录，然后计时，结束后删除 `exclusive`。单次独占不超过 15 分钟。
- 验收运行：启动前确认没有 `exclusive`，然后 `mkdir gpu-locks/shared-<代理>-<编号>`，运行结束后删除。每个代理同时最多 2 个验收运行。
- 主会话的最终测量在三个子代理都结束后进行，以它为准。

## 阶段一与阶段三画面（子代理 A）

### A1 渲染去掉无效计算

**文件：** `rendering.py`、`visual_surface.py`、`test_core.py`

- `EndoscopicView.update` 不再细分曲面（实测细分前后图像平均差 0.01/255）。`refine_surface` 如因此无人使用，连同 `visual_surface.py` 和 `test_visual_refinement_preserves_separated_cut_faces` 一起删除；若仍有用途则保留。
- 器械网格（夹钳、剪刀刃、腕部、轴）形状不变，只是位姿变化：一次创建，之后每帧只更新节点位姿；组织网格每帧重建（拓扑会变），直接用数组构建 pyrender 图元，避免 trimesh 中转。
- `capture`：暗角预先算好；只有超采样时才缩放；新增参数选择是否渲染深度（只有 `initial` 需要深度）。
- 超采样倍数成为 `EndoscopicView` 参数：录像（`--demo` 等无窗口录制）保持 2 倍，实时窗口用 1 倍（渲染器已有 4 倍 MSAA）。
- 验收：同一保存状态下新旧出图（2 倍超采样）平均差 < 1/255；每帧（更新 + 出图）在 1 倍、无深度时 ≤ 30 ms，2 倍时 ≤ 50 ms（独占 GPU 测量）。

### A2 每步刀背重叠质检提速

**文件：** `instrument_geometry.py`（`scissors_body_depths`）、`test_core.py`

- 先按刀身包围球（铰点为心、半径为刃长加盒体与腕部包络）剔除远处采样点，只对附近采样做盒体与胶囊测试。结果必须与全量计算逐值相同（远处点不可能重叠）。
- 验收：在 3 个保存状态（含剪切中）上新旧结果完全相等；每步耗时 ≤ 2 ms。新增测试：随机远点不改变结果。

### A3 实时窗口按墙钟播放

**文件：** `run.py`

- 非 `--headless` 且非 `--native-only` 时进入实时模式：物理（含每步验收记录、轨迹写入、原生库全部调用）在工作线程中运行，按墙钟节拍推进（模拟时间超前墙钟时等待，落后时全速）；主线程持有 OpenGL 与 OpenCV 窗口，取最新快照（表面数组与观测的拷贝）出图并显示。原生库只在工作线程中调用。
- 实时模式的录像：以固定帧率（与显示一致，例如 30 fps）按墙钟时刻写入当时最新显示的帧，与观看到的播放一致；确定性录像仍用 `--headless --demo`（同步路径，每 N 步一帧）。
- 空格暂停、Q/Esc 退出保持；暂停时物理也暂停。终端打印每阶段的“模拟时间 / 墙钟时间”比值和显示帧率。
- 验收：`wall-traction` 实时运行通过全部验收；报告每阶段实时率（模拟时间/墙钟时间）与显示帧率；`--headless --demo` 录像与改动前逐帧相近（同一 DLL、同一流程，抽查关键帧）。

### A4 内窥镜光照与湿润质感（阶段三画面）

**文件：** `rendering.py`

- 光源跟随镜头：在相机位置加一个点光或聚光（随相机位姿更新，包括结尾推近），光强随距离衰减；固定的环境光与补光减弱到只防止全黑。
- 湿润质感：组织与切面降低粗糙度、增强高光；切面颜色更深更饱和的红（渗血感）。
- 轻微镜头效果：桶形畸变与暗角（预先算好映射表，`cv2.remap`），可选轻微色差；每帧额外耗时 ≤ 3 ms。
- 验收：给出改动前后同一状态的对比图；每帧额外耗时 ≤ 3 ms；画面不出现过曝或全黑区域（高光像素占比、暗部占比给出数字）。

## 阶段二：物理算法优化（子代理 B）

**文件：** `native/vendor/**`、`native_backend.py`（绑定、子步数）、`scenario.py`（仅 `scissors_settings` 子步数）、`test_core.py`

### B1 计时手段

- 用 Python 包住各原生调用计时（`LCS_Step`、`LCS_Finalize`、`LCS_RefineContactSurface`）并读取内置 GPU 计时（`LCS_ProfileEnable`/`LCS_ProfileRead`）；需要更细时在原生代码中临时加 CUDA event 区段计时（只在开发构建中启用，最终保留为可选开关或删除）。Nsight Systems 需要管理员权限，不可用。
- 参考脚本：`scratchpad/run_native_split.py`（按阶段拆分耗时）、`scratchpad/bench_physics.py`（空闲基准）。

### B2 子步数 3 → 1（仅剪刀设置）

- `scissors_settings()` 设 `substeps=1`（单刀片流程不变）。已有单次运行通过全部验收；需要按验收协议补足运行次数。若出现不稳定或验收退化，改用 2 并报告。

### B3 接触曲面修复（`LCS_RefineContactSurface`）

- 现状：夹持后每步 12–14 ms。每轮先测穿透深度，超过容差就重建接触曲面与整个重建，最多 8 轮；夹钳钳口内本应存在、无法修复的穿透让循环一直跑到“停滞”判定（约 3–4 轮完整重建）。
- 做法：找出持续触发修复的穿透来源（预期是被夹持区域或钳口内组织），让深度判定排除这些不可修复的部分，或首轮无改善即退出；保留对真正可修复穿透的修复。不得增大非刃口重叠。
- 目标：夹持与剪切阶段该项 ≤ 3 ms/步，非刃口重叠与表面拓扑验收不变。

### B4 子步求解（`LCS_Step`）

- 现状（1 子步）：空闲 20 ms，夹持 27 ms，剪切 32–33 ms；几乎全部在子步的第一段（弹性求解与工具接触）；每子步约 5 ms 固定开销，xpbd 求解器里有 41 处设备到主机拷贝或同步、36 个单线程核函数。
- 做法（按测量结果排序实施，每项单独验证）：
  1. 去掉子步内不必要的主机同步与设备到主机拷贝（改为设备端判断、固定上界或延迟到帧末）。
  2. 合并相邻的单线程核函数；把每子步固定的核函数序列捕获为 CUDA Graph 重放。
  3. 工具接触搜索（每种刃/刀背/腕部各遍历全部表面三角形）先按工具包围盒剔除远处三角形。
  4. 弹性求解的着色遍数与收敛：在不改变结果精度（对比位移与验收）的前提下减少冗余遍数或提前收敛退出。
- 目标：剪切阶段 `LCS_Step` ≤ 22 ms/步（中位数）。

### B5 验收协议（每个原生改动合并前）

- `wall-traction` 3 次全部通过；`wall` 2 次无新的失败类型；`flap` 2 次通过；单刀片流程用新 DLL 1 次通过；`test_core` 全过。
- 报告：改动前后按阶段的耗时表、验收结果、新 DLL 哈希。

## 阶段三物理：摩擦夹持（子代理 C）

**文件：** `scenario.py`（`Sequence` 夹持相关、`wall_stages` 夹持参数）、`native_backend.py`（接触模型调用与相应 `Settings` 字段）、`test_core.py`

- 原生库已支持三种接触模型：0 旧代理、1 表面接触 + 纯库仑摩擦、2 在 1 的基础上加持久锚点（现用）。薄壁两个场景改用模型 1：钳口只靠法向压力和摩擦夹住组织，拉力过大会打滑。
- 夹持验收重定义（模型 1 下 `grip_points` 不再表示锚点）：
  - 夹住：闭合阶段结束时钳口内有组织且受到法向压力（用钳口体积内的材料节点与接触反力判定，给出阈值依据）。
  - 提起：夹住时位于钳口体积内的材料节点，其中位上移不小于 1 mm（与原 `lift_m` 同阈值）。
  - 打滑：从闭合到结束，这些节点相对钳口坐标系的中位滑移，作为新指标记录；不超过 1 mm 才通过（理由写在代码注释里）。
  - 不能放宽剪刀相关的任何验收。
- 调参范围：钳口摩擦系数（锯齿钳口与湿组织，文献约 0.3–1.0）、闭合间隙/夹紧程度、提拉速度；参数需物理上说得通。
- `flap` 与单刀片流程暂保留模型 2；若薄壁场景成功，另行报告扩展到它们的可行性。
- 接线：在 `native_backend.py` 的 `Settings` 加接触模型字段（`NativeTissue` 初始化时用它调用 `LCS_SetContactModel`），在 `ScissorsScene` 加同名字段，薄壁两个场景设为 1。`run.py` 里把场景的值写进 `settings` 的那一行由主会话在合并时添加；C 自己测试时用临时包装脚本覆盖设置，不改 `run.py` 和 `scissors_settings`。
- 验收：`wall-traction` 3 次、`wall` 2 次通过全部验收（含新的夹持指标）；给出夹持阶段的对比帧（锚点 vs 摩擦）。

## 结果（2026-10-28）

- **画面与实时窗口（A）**：每帧 1 倍 23–25 ms、2 倍约 44 ms（原 300–355 ms），刀背重叠质检约 5 ms/步（原 15 ms），窗口按真实时间播放、录像记录屏幕画面；内窥镜光源跟随镜头、湿润高光、平滑着色、深红切面、0.08 桶形畸变。
- **物理提速（B）**：子步数必须保持 3（1 或 2 个子步时起切挤压不到位、刀背重叠超标）。碎块接触、刀刃扫描、顶点扫掠、颜色组装、拓扑刷新去重和线程束协作组装合计，每步物理从 64/93/113 ms（空闲/夹持/剪切）降到 44/58/65 ms，结果在舍入误差内一致。B3（跳过夹持时的接触修复）会让第三刀剪错层，未采用；B 查明修复每步都触发，是因为判定时用的是指令中完全闭合的钳口位姿，而不是实际被组织撑开的位姿，改用实际位姿每步约省 6 ms，但改变现有物理，需要另行验证。
- **摩擦夹持（C，B 补原生）**：持久静摩擦已实现（粘着点在摩擦锥内固定在钳口上，拉力达到约 0.6 倍压力开始滑动），但钳口压力只有 0.5–1.5 N，剪刀拖拽超过静摩擦，纯摩擦夹持在两个薄壁场景和薄瓣都会脱落；场景保持锚点夹持，等待用户决定是否加大夹紧力或改为闭合锁定的钳口。
- **切口跟随变形组织（主会话，用户追加）**：见 [剪刀设计与验证](scissors-realism-design.md) 最后一节。
- **合并验证**（DLL `2a8023f1`）：`wall-traction` 3/3、`wall` 1/2（原有刀背问题 0.23 mm）、薄瓣、单刀片通过，`test_core` 18 项通过；已替换 `bin-scissors`。剪切阶段窗口播放约为真实速度 0.46 倍，空闲约 0.65 倍。

## 风险

- 阶段二能否把剪切阶段压到预算内取决于测量结果，无法事先保证；未达标时报告剩余差距与可选办法，不擅自降低真实感。
- 摩擦夹持可能在提拉时打滑；调参仍不能稳定夹住时报告，并保留锚点夹持作为现状。
- 三个代理共用一块 GPU：计时必须独占，验收运行会变慢。
