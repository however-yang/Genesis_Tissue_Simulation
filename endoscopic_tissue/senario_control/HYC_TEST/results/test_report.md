## 衔接与验证范围

[`instrument_driver/motion_bridge.py`](../../instrument_driver/motion_bridge.py) 接收外部字典或 JSON 解析结果，
连接自定义 `Grasper` 和 `Scissors` 实例。驱动文件于 2026-11-12 移至独立的 `instrument_driver` 目录。
输入包括两把器械的底座位姿、四关节目标角和剪切标记；输出包含当前角、目标角、速度、位姿和间隙。

已验证：

- 默认器械配置和场景配置能够加载。
- 设置目标不推进时间；两把器械的目标和底座互不影响。
- 同步步进遵守每个关节的速度限制。
- 整体平移使各部件移动相同距离；只更新底座方向时保留位置。
- Pitch 绕实际关节位置转动，后续关节位置与独立计算的预期相符。
- 两瓣尖端距离等于输出间隙，部件旋转矩阵保持正交且行列式为 1。
- 平滑轨迹到达目标，首末步速度较小，峰值速度满足配置限制。
- 平滑迭代器支持暂停继续；过短时长及不支持的底座过渡被拒绝。
- 非有限值、越界角、错误数据形状、错误字段与错误步长被拒绝，状态不发生部分更新。
- 修改输出快照不会修改器械实例。
- 外部反馈不覆盖控制角；错误反馈不覆盖上一次有效反馈。
- 在新 Python 进程中导入并创建衔接器，不会加载组织网格、原生后端或 CUDA 适配器。
- JSON 样例的逐步输入能够驱动实际器械实例，输出可序列化且无 NaN/Infinity。

## 测试发现并修正的问题

1. **默认剪刀配置无法初始化。** 两个配置文件中的 `initial_deg = 79.99989` 略高于
   `degrees(1.39626)` 模型上限，触发关节配置校验。
   已将自定义运动配置和自定义场景配置中的初始值下调为 `79.9998`，保留模型角度上限。
2. **外部反馈缺少校验。** `ArticulatedInstrument.observe()` 会接收错误长度位置、NaN、负间隙或
   超出几何范围的间隙，并覆盖有效反馈。已在写入反馈前校验位置与间隙，使用真实间隙换算开合角。
3. **新衔接文件的向量校验不完整。** 零维 NumPy 数组导致 `len()` 抛出 `TypeError`。
   已先检查维数，并统一拒绝错误向量形状；同时拒绝非字符串字段名。

## 2026-11-12 单步驱动职责调整

驱动接口改为 `MotionBridge(grasper, scissors)`，必须由外部提供已有实例。
驱动不再加载配置、创建器械、维护时钟和步数，或执行整段过渡。
每次 `step(input, dt_s=...)` 只计算一次空间位置、朝向和关节更新。
新增世界坐标系线速度与角速度输入；外部指定的绝对位姿仍然受支持。
`submit()` 仅暂存数据，实例在下一次外部步进时更新。
平滑轨迹测试改由外部采样器配合单步驱动完成，没有增加场景管理模块。
