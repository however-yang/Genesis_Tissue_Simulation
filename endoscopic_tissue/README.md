# 内窥镜软组织夹取与切割原型

这是独立放在 Genesis 仓库中的原型。**不需要启动 Unity**，也不会连接、重置或改写原 Unity 工程。组织与器械接触由复制并独立编译的 CUDA 核心计算，Genesis 提供场景和相机渲染。

当前场景：约 **60 × 40 × 14 mm** 的软组织块、底部附着，左侧 Cadiere 夹钳。默认演示使用 **dVRK 179 单极弯剪**：厚块顶面前缘立着一道 25 × 7 × 4 mm 的薄壁，物理网格 1 mm。剪刀从右前方斜着进入、躺在薄壁半高的水平面内连剪三刀：每刀两刃先压住组织、挤压变形达到起切条件后才剪开，断边跟随刀刃，切口就在刀口下。第一刀后夹钳夹住剪开的上片自由端提起 4 mm，露出切面；剪刀每次原地张开、沿壁滑 5 mm 再剪下一刀。三刀沿壁长剪出 11–15 mm 的伤口，切面为红色。`--scene flap` 运行原薄瓣三刀剪断流程（夹钳先夹住厚块提拉；6 × 4 × 20 mm 悬空薄瓣，从自由端剪到根部）。`--tool knife` 运行原单刀片流程（**16 mm** 有限切割刃）。剪刀设计、起切判定和验证见 [剪刀设计](docs/scissors-realism-design.md)。

历史单刀固定轨迹已在两次独立回归和一次 Genesis 录像中通过夹取、拉伸、单刀片切割和退刀验收。 默认网格为横向 2 mm、切入方向 0.5 mm。新增切面端点重建和退刀保护，详细数据、适用范围和录像见 [单刀片稳定性记录](docs/cut-stability.md)。旧失败记录保留在 [接触优化记录](docs/contact-optimization.md)。

此前器械版本的多次切割结果：0° 换位切割、45° 沿原切口重复进刀，各有一组通过并完成录像，使用不同的已记录构建；90° 重复切割仍有节点失稳。详见 [重复切割记录](docs/repeated-cutting.md)。加长演示保存在 `outputs/long-demo-20261027/`，来源与构建对应关系见 `provenance.json`。

## 达芬奇器械与脂肪外观

默认夹钳使用 [dVRK Cadiere 8 mm 模型](https://github.com/zixingjiang/dvrk_description)，包含镂空齿形钳口和分节腕部，保留原仓库 MIT 许可及来源记录。模型为研究用 Classic 器械网格，并非厂家认证的 Xi/X 数字孪生。默认钳口长 19.9 mm、宽 5.2 mm；轴杆与腕部采用约 8 mm 包络。根据较长钳口调整了接近位置，钳口接触代理由同一组顶点计算。默认刀向为45°，单次切入目标为原生y=+0.15 cm；原0°深切仍有接触与切面问题，失败记录保留。

单刀片保留原切割方式，采用公开腕部和参考 Snap-fit 外观制作的简化刀片装配件，**不是原厂 Snap-fit CAD**。镂空和细齿仍采用包围盒接触近似，腕部由保守轴杆包络覆盖。刀刃和刀背显示对应实际接触位置。

可操作组织块及切面改用淡黄色脂肪纹理；周边背景保留红色组织。贴图由内置 ImageGen 生成，原生 1254 × 1254，文件与完整提示词位于 `assets/textures/fat/`。纹理通过材料坐标绑定，拉伸时随组织运动。此处修改的是外观，材料参数仍为原有未标定软组织参数。

改动设计和结果见 [器械与脂肪外观记录](docs/davinci-fat-design.md)。原始预览录像与检查输出位于 `outputs/davinci-fat/`，不含侧边讲解。

## 双刃剪刀

剪刀使用 dVRK 179 单极弯剪网格，组织与两刃、刀背和腕部的接触、起切和切面重建由 `native/bin-scissors/` 的 DLL 计算。起切条件：剪刀正在闭合；左右刃各自沿闭合方向压在组织上的载荷（刃口与刀身合计）都不小于起切力的一半（默认每片 0.1 N）；并且两刃都开始受力后刀尖已再闭合 2 mm（`scissors_squeeze_cm`）。在此之前刀刃只压缩、推动组织，不改变拓扑。

切口跟随刀刃在变形组织里的实际位置：剪刀闭合时，组织中此刻正好位于剪切面上、并且刃口已经扫过（或到达半个网格以内）的那一层被剪开。每一列组织（沿剪切面法向的一列节点）只剪一次，剪在哪一层由刀刃经过时组织的位置决定。夹钳牵拉、刀刃挤压和剪刀受力下沉造成的形变，因此会让切口在材料里上下起伏、跨层；相邻两列剪在不同层时，两列之间的连接一并剪开，伤口始终是一整片连续的面。组织外侧那一圈表皮节点照抄紧邻组织列的高度。验收另外检查起切时两刃载荷、两刃同时受力后的挤压行程、断边只在目标组织内、目标范围内每一列恰好剪断一次（不留连接，也不剪出夹层碎片）、表皮切口都紧挨着组织切口、剪后连通性和每阶段的表面拓扑。

当前结果（DLL `2a8023f1…`）：每刀都在两刃各自达到起切力一半并挤压到位后才剪开，拓扑和连通性检查全部通过。`wall-traction` 6 次运行 6 次通过，刀背压入 0.02–0.11 mm；靠近被夹提的自由端，切口比原定平面低一层（1 mm），伤口长 15–16.5 mm。`wall` 4 次中 3 次通过，第二刀的切口比原定平面低 2 mm：夹钳提起第一刀剪下的组织条时，带着未剪的墙体一起上移。失败的一次与旧剪切逻辑下相同：后两刀远刃刀身推着剪切面下方剪不到的下半壁，刀背压入 0.23 mm，超过 0.2 mm 的非刃口重叠验收线。薄瓣三刀流程和单刀片流程通过。默认 DLL 现为 `423927eb…`（三轮提速和外壳释放）。复测：`wall-traction` 和单刀片流程通过；`wall` 10 次 9 次通过、薄瓣 5 次 3 次通过，提速前的构建同日分别是 14 次 9 次、4 次 1 次。失败都是已知的几种：刀背压入略超 0.2 mm、个别列没剪断、偶尔有组织飞出工作范围。其他限制：同一连通体内切口两侧切面之间没有接触；弯曲刃口按平直剪切面近似；组织参数未标定。详见 [剪刀设计与验证](docs/scissors-realism-design.md)。演示录像在 `outputs/final/demo-traction/`；上一版（切口固定在一个材料平面上）在 `outputs/scissors-follow/demo-8/`，6 mm 薄瓣录像在 `outputs/scissors-demo2/run-1/`。

## 肾脏肿瘤切除

`--scene kidney`：真实尺寸的肾脏（长 11 cm、宽 6 cm、厚 3.5 cm），外侧凸缘朝上，凸缘上有一个直径 1.5 cm、凸出约 1.15 cm 的外生肿瘤。整个肾脏都按 1 mm 网格参与形变，下部埋在肾周脂肪里并固定。夹钳夹住肿瘤顶部，提高 16 mm 保持牵拉，肿瘤上升 7–12 mm，根部被拉成颈。剪刀放平从右前方进入，两刀剪断颈部；剪刀退出后，夹钳把切下的肿瘤再提起 1 cm。外观包括带细血管的深红褐色肾包膜、金黄带分叶和出血斑的肿瘤、红色实质切面和黄色肿瘤切面，周围是肾周脂肪。

结果（DLL `2dd3d584…`）：肿瘤整块切下，按组织连接和按全部模拟连接都分成两块，肾脏上不留肿瘤组织，肿瘤在钳口里被提起，肾脏残端回到夹持前的形状（最多高 0.56 mm）。肿瘤边缘下方窄缝里的外壳连接由原生代码的外壳释放剪开：剪刀每次剪断后，两端分属不同组织块的连接都会剪开。每刀都在两刃各自受力并挤压到位后才剪开，刀背压入不超过 0.04 mm。三轮提速以后每步 76–104 ms，约 0.32–0.44 倍实时（提速前约 0.2 倍）；整个肾脏按 1 mm 网格计算时到不了实时，原因和剩下的办法见设计记录。**尚未通过：**两项判据待定。一是外壳释放剪开的两块之间的表皮连接被算作游离表皮切口（33–40 条）；二是第一刀的裂尖落在弯曲表面上，产生 1–3 条“三角形共边”，第二刀后消失。录像和截图在 `outputs/kidney-release-20261028/`，修复前的在 `outputs/kidney-wip-20261028/`。详见 [肾脏与肿瘤设计](docs/kidney-tumor-plan.md)。

## 启动

在这台电脑上双击 `run_demo.cmd`。它使用现有 `genesis_world` Python 环境，打开内窥镜画面；空格暂停（任意键继续），Q 或 Esc 停止。演示结束后保留最后一帧，按任意键关闭。

窗口按真实时间播放：后台线程推进物理，每步对应 1/30 s。算得比真实时间快就等待；算得慢就全速运行，之后也不追赶，所以播放速度不会超过真实时间。主线程只显示最新算出的状态。窗口录像按 30 fps 记录屏幕上实际显示的画面，暂停的时间不计入。窗口模式下阶段截图和收尾特写都按 1 倍分辨率渲染。每个阶段结束时终端打印该阶段的实时倍率、每步耗时和显示帧率。

每步耗时（RTX 3090，3 个子步，含全部检查）：空闲 44 ms、夹持 52 ms、剪切 58 ms；优化前物理部分是 64、93、113 ms，另加约 7 ms 检查。刀背重叠检查、断边统计、轨迹记录和验收指标都在后台线程里算，与下一步物理并行；物理线程只读一次表面（约 0.5 ms）。接触修复按钳口实际求解出的位置测量穿透：夹持时钳口被组织撑开，按指令里的闭合位置测会每步误报约 0.3 mm 穿透并白做一次修复。窗口播放大约是真实速度的 0.76 倍（空闲）到 0.57 倍（剪切）。子步不能再减：1 或 2 个子步时，有的刀两刃挤压不到位就剪断，刀背也会压进组织超过 0.2 mm。

也可在 **D:\Simulation\genesis-world** 下运行：

```bat
D:\develop\anaconda3\envs\genesis_world\python.exe -m endoscopic_tissue.run
```

导出完整视频和截图，不打开窗口：

```bat
D:\develop\anaconda3\envs\genesis_world\python.exe -m endoscopic_tissue.run --headless
```

只看初始场景：

```bat
endoscopic_tissue\run_demo.cmd --steps 0
```

`--demo`（剪刀流程，需要画面）全程固定中景，剪刀最后退出后推近到伤口并定格 3 秒；物理流程与验收不变。`--scene wall|wall-traction|flap|kidney` 选择剪刀场景（默认 wall）；`wall-traction` 让夹钳在剪切前先夹住薄壁自由端顶部提起 1.2 mm，剪刀再进入，每剪一刀夹钳再提 0.5 mm。`--tool knife` 切换为单刀片流程。`--start-force` 改起切力（牛顿，剪刀每片刀刃需达到其一半），`--dll` 指定原生库。`--viewer` 额外打开 Genesis 自由观察窗口。`--native-only` 只运行物理流程。`--render-every N` 设定每隔几步取一次状态来画：窗口模式默认 1，尽量显示最新状态；`--headless` 默认 3，即每 3 步一帧、视频 10 fps，且与物理同步，不按真实时间。窗口模式下若达不到实时，`--render-every 2` 可以把渲染负担减半。每次运行在 `outputs/时间戳/` 创建新目录；显式 `--output` 必须指定尚不存在的目录，避免覆盖实验。

已有依赖：Genesis 本地源码、NumPy、trimesh、Pillow、OpenCV。原生后端需要 Windows x64 和 NVIDIA CUDA GPU；随附 DLL 为 sm_86，在本机 RTX 3090 上验证。换 Python 路径可设置 `ENDO_PYTHON`。这不是 CPU 组织求解器，`gs.cpu` 仅用于轻量 Genesis 场景。

## 画面与材质

- 可操作组织和切面使用生成的脂肪颜色/法线贴图；背景保留原 Unity 肝组织材质。
- 光源模拟内窥镜：灯装在镜头上，跟随相机移动；亮度按到注视点距离的平方补偿，类似内窥镜的自动调光，近景和中景曝光一致。另外只有两盏很弱的补光。不计算阴影，因为镜头上的灯投下的阴影基本藏在物体自身背后。
- 组织表面是低粗糙度的湿润材质，灯光下会出现高光点。切面颜色比完整表面更暗更红，像渗血的脂肪。
- 组织纹理绑定静止材料坐标，随组织运动；侧面独立投影，减少拉伸。
- 显示网格直接使用物理表面三角面，按重建给出的顶点法线平滑着色。不再细分：细分后的画面与不细分几乎逐像素相同，每帧却多花约 100 ms。
- dVRK Cadiere 钳口模型与接触代理共用铰点、开合轴和末端尺寸，跟随 CUDA 求解后的位姿和开度。
- 单刀片包含有限刃口、刀背和刀杆接触体；只有刃口能触发切割。
- 默认输出 1280 × 960。`--headless` 以两倍宽高渲染，再用 Lanczos 滤波缩小。窗口模式直接按 1 倍渲染，靠渲染器自带的多重采样抗锯齿，边缘略有阶梯。最后都加 0.08 的桶形畸变和内窥镜暗角。
- 每帧耗时（RTX 3090）：1 倍 23–25 ms，2 倍约 44 ms；改进前 2 倍为 300–355 ms。

平滑法线只改善显示。它不提高物理网格分辨率，也不构成真实次表面散射或组织光学标定。周边组织是移出操作区的视觉背景。钳口使用模型末端包围盒作为接触代理，细小凹槽未建模。刀刃为有限胶囊、刀背与刀杆为有向盒，尚非完整手术刀接触网格。

## 验收与输出

`report.json` 明确区分 `passed`、`partial`、`failed`。`--steps` 提前结束、用户退出或只看初始帧都不算通过完整验收。验收要求：

1. 闭合后捕获实际材料节点。
2. 同一批节点的中位提拉高度至少 1 mm。
3. 进刀前无断边，切割阶段新增断边。
4. 重建出切口内壁三角面。
5. 退刀并保持后，原切割阶段的断边仍全部存在，夹持仍有效，且没有新增断边。
6. 每阶段检查没有退化面、开放边界、非流形边、重复面或绕序异常；整个流程刀背/刀杆重叠不超过 0.2 mm。
7. 材料节点相对初始位置的位移不超过 60 mm 操作范围；越界立即停止。

`cut_edges` 是**被切断的无向网格边数**，包含边界单元的空气区连接，不能直接当作真实组织切割数量、毫米数或伤口面积。验收同时检查真实内壁、断边保留和退刀不新增断边。独立评估程序还逐帧检查内壁退化。

输出包含 `trajectory.jsonl`、阶段 `.npz`、阶段 `.png`、`endoscopic_demo.mp4`、初始深度 `.npy`。状态数组后缀 `_cm` 为原生厘米坐标；深度 `_m` 为米。图像有镜头畸变和暗角；深度是未经畸变和暗角处理的针孔相机采样。

## 当前物理边界

粗网格曾产生外层孤立节点和越界切面。当前使用真实刃口前缘扫掠，并将切入方向细化至 0.5 mm，切面按各侧连通分量生成，剔除裂口前缘的内部重复面和零面积半面；没有冻结或隐藏异常节点来通过验收。

单刀片流程仍偶尔会把一个节点切成孤立点（2026-10-28 查明）：判断连接是否穿过刀刃的两项检测，允许穿过点略微超出连接两端（1e-5 和 2%），再把它收回到端点上。节点贴在刀刃面上，或从刀刃线旁擦过时，它朝两侧的连接会在节点这一端一起切断，节点要么完全孤立，要么只剩一条连接吊着，随后掉出 60 mm 工作区。修复前大约 5 次失败 1 次，B 提速前的版本也同样失败过。现在的规则是：穿过点必须落在连接上，恰好落在节点上时只算连接的远端，贴着刀刃的节点固定留在一侧。修复后 6 次单刀片运行全部通过，最大位移 8.6–8.7 mm，再没有切口贴在端点上的成串断开。修复在 `native/bin-scissors/`，剪刀和单刀片流程现在都默认使用它；原始的 `native/bin/` 保留不动，仍是旧代码，需要对比时用 `--dll endoscopic_tissue/native/bin/LiverCudaSim.dll`。

这不是任意方向切割的通用重网格方案。固定全部材料的刚性极限、任意刀向、反复切入、不同网格相位和更粗分辨率仍需单独验证。当前有限元会按断边停用体单元，未实现局部虚拟节点或体网格重新划分，不能据此声称网格收敛。

当前是**器械末端控制原型**。CUDA 同时计算组织形变、工具有限质量驱动、夹持与切割反力；Genesis 显示这些实际位姿。尚未接入 Genesis 机械臂关节动力学、RCM 约束或原生刚体双向耦合，也没有训练好的策略。夹持包含显式柔性锚点（接触模型 2）。只靠钳口压力和摩擦的夹持（接触模型 1）有持久静摩擦：组织在摩擦锥内时，粘着点固定在钳口上，跨子步、跨帧保留，拉力超过 0.6 倍压力才开始滑动。但现在的钳口两片合计只压住组织 0.5–1.5 N，剪刀合拢或提拉时的拖拽力超过静摩擦，薄壁组织会在第一或第二刀被拖出钳口，薄瓣在提起时就滑脱。要靠纯摩擦夹住，需要更大的夹紧力，或者像真实器械一样闭合后锁住的钳口。模型 1 的验收（两片钳口都受压 0.05 N 以上、提起至少 1 mm、滑移不超过 1 mm、没有脱落）已经写好。组织参数未用实验标定；自碰撞和医学精度未验收。原生模块为单会话，不能在一个进程中建立多个独立环境。

| `run.py` | 启动、阶段执行、结果记录、视频与窗口 |
| `scenario.py` | 控制路径及基于真实状态的验收 |
| `native_backend.py` | ctypes ABI、原生组织与工具接口、状态和切面读取 |
| `grid.py` | 程序化实体、材料邻接、Hermite 交点、4096 项连通表 |
| `rendering.py` | Genesis 相机、光照、PBR 组织和器械显示 |
| `visual_surface.py` | 不跨裂面连接的显示细分 |
| `instrument_geometry.py` | 显示与碰撞共用的钳口和刀片几何 |
| `assess_interactions.py` | 重复夹取/切割、松钳和不同网格配置的实际评估 |
| `probe_cut_topology.py` | 固定/运动组织对照，导出空气与材料断边诊断 |
| `probe_grasp.py` | 独立验证夹取、提拉、保持和释放 |
| `probe_knife_contact.py` | 刀背接触的固定组织正负对照 |
| `inspect_cut_surface.py` | 从保存状态生成同机位切前/切后近景与几何检查 |
| `native/vendor/` | 独立 CUDA/C++ 副本，已加入单刀片非刃口接触 |
| `native/bin/` | 原始的单刀片 DLL，保留不动，不再默认使用 |
| `native/bin-scissors/` | 默认 DLL（剪刀和单刀片流程）：双刃起切判定（载荷与挤压行程）、刀背与腕部接触、跟随变形组织的剪切、夹钳持久静摩擦、单刀片穿刃判断修正 |
| `native/bin-realtime/` | 实验构建的输出目录，验证通过后再复制到 `bin-scissors/` |
| `assets/` | 脂肪纹理、公开 dVRK 器械网格、原项目背景材质及来源记录 |

Genesis 的外部网格接口集中在 `rendering.py`，因为公共 debug mesh 默认不参与正常光照。这个适配层针对当前 Genesis 1.4.5；升级引擎后需复验，不需要修改 Genesis 源文件。

## 编译与检查

```bat
endoscopic_tissue\native\build_native.cmd D:\Simulation\genesis-world\endoscopic_tissue\native\bin-scissors
D:\develop\anaconda3\envs\genesis_world\python.exe -m unittest endoscopic_tissue.test_core -v
D:\develop\anaconda3\envs\genesis_world\python.exe -m endoscopic_tissue.smoke_native --steps 3
```

构建脚本使用本机 VS 2022 与 CUDA 12.5，输出只进入本目录。不传参数时输出到 `native/bin/`，会覆盖原始的单刀片 DLL，所以始终传输出目录：按上面的命令输出到默认的 `native/bin-scissors/`，或先输出到 `native/bin-realtime/` 验证。换机器需调整脚本中的工具链路径和 CMake 的 GPU 架构。`native/source_manifest.json` 保存复制时的来源哈希，`native/build_info.json` 保存本次独立编译结果。

`NativeTissue.step(Command(...))` 是后续外部控制或训练环境的接入点。`Command` 接受夹钳目标位置、闭合量和刀刃目标位置，位置使用厘米；`Observation` 返回实际节点、拓扑、夹持状态、工具位姿与反力。先保证这个单环境物理基线，再增加机械臂和训练封装。
