# S15 原生实现草案（尚未实现，不能视为验收）

完整状态不止节点/速度。初步方案采用独立编译单元中的显式状态登记，避免对进程或 GPU 内存做不受控扫描。

- 在隔离构建中登记 cudaMalloc/cudaFree 的分配地址、字节数、来源；默认源码不动。第一版保守保存所有存活分配，随后只在有写前不读证明时剔除临时区。
- 各原生模块导出本模块主机状态清单。标量/POD/向量显式序列化；CUDA graph/stream/event 是执行资源，不能当物理状态序列化。恢复时销毁失效 graph 并重建，保持物理缓冲值。
- 指针必须归一化为 allocation ID + byte offset，不能保存可直接重用的裸设备地址。主机指针别名、设备 UnifiedState/MultigridLevel 等含指针结构都需要显式类型字段描述。禁止猜测内存中的整数是否像指针。
- 恢复先完整验证 schema/大小/校验和，再准备所需分配及地址重绑定，随后恢复全部主机/设备/constant symbol 状态。动态图大小变化需要处理多出的分配，不能把旧地址留给 graph。
- 每个静态/全局/函数静态跨步变量、所有 CUDA symbols、每个分配点均盘点，自动枚举只能作为漏项检查，不能代替审查。
- Python 快照保存不可变 bytes（本地安全的结构化状态序列化优先），不返回可被修改的共享 dict/ndarray。持久化使用明确格式、校验和，不无条件执行 pickle 内容。
- 先证明 T1/T2/T3/T5/T6，再进行高开销 T4/T7/T8。若保守状态超过 200 MB，报告实际大小，不能删必要历史凑大小；按真实读写依赖再压缩/重算。

本方案仍待 buffer/host/symbol 盘点和实现。不要宣称已有快照功能。
