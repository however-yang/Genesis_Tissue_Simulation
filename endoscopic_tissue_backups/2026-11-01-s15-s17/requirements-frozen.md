5. **先有把握再动手。** 实施前要有 95% 的把握，不清楚的地方先问用户。

## 2 S15 状态快照与分叉

### 2.1 为什么

**现状**
- 原生约 80 个 `LCS_API` 导出里，没有保存或载入状态的接口。
- `reset` 只能销毁会话、重建，再跑一遍准备脚本：我们关闭全表面检查时每次 11.5 s，作者记录的是 35–37 s。

**谁需要**
- WAM 的分支实验要从同一个状态出发比较多个候选：每个状态 27 个候选 × 2 次重复，在 `is_squeezing` 开始时还要第二次分叉。
  - 现在只能从头重放前缀。
  - 可是同一串命令重放时，第 2、3 剪的起切时刻是双峰：一次在第 35 步，其余在第 48–50 步。
- VLP 如果用这个仿真器做分支标签，同样依赖快照（v4 第 5.4 节）。

15 号清单当时把快照列为后续的加速项；现在它已在 WAM 的关键路径上。

**没有它时的退路：** 按 seed 配对、重放前缀，代价是要更多重复，置信区间也更宽。

### 2.2 接口（建议）

**Python，挂在 `NativeEnvironment` 上：**
- `snapshot() -> EnvSnapshot`
  - 只能在一步结束后调用；
  - 返回不可变句柄，里面有原生状态字节、Python 侧状态和元数据。
- `restore(snapshot, *, branch_label=None)`
  - 恢复后开启一个新的分支回合；
  - 同一快照可以反复恢复。
- `EnvSnapshot.save(path)` / `EnvSnapshot.load(path)`
  - 可选落盘；
  - 载入时校验 DLL SHA、ABI 和配置哈希，任一不一致就拒绝。

**原生：**
- `LCS_StateAbiVersion()`
- `LCS_StateSize(size_t* bytes)`
- `LCS_SaveState(void* buffer, size_t capacity)`
- `LCS_LoadState(const void* buffer, size_t size)`

调用时机：只在 `LCS_Finalize` 之后、下一次 `LCS_Step` 之前有效。

### 2.3 必须保存的状态

**总规则：** 每个跨步存活的设备或主机缓冲都要归入下面三类之一，并写进一份清单文件。参考规模：`native/vendor/cuda` 下约 250 处 `cudaMalloc`，其中 `xpbd/xpbd_solver.cu` 有 156 处。
1. 保存；
2. 可由已保存的内容重算（附测试）；
3. 每步先写后读的临时区（附理由）。

至少包括：

| 类别 | 内容 |
|---|---|
| 组织 | 节点位置；求解器内部速度（不是差分速度）；活动、固定与质量标记；材料体积状态 |
| 拓扑与切割 | 邻接；静止邻接；断边分数；各列的切割层与列主轴；`cut_init` 时的拓扑快照；撕裂标记；夹持豁免环；拓扑与表面的修订号 |
| 夹持与接触 | 锚点，含 `graspCore`、`grasped`、`coreForceEMA`；捕获/释放状态机；见证点；摩擦与接触历史；钳口的求解位姿与动力学 |
| 剪刀 | 相位；两侧载荷累积；挤压累积与挤压起点开度；断裂锁存；freeTravel；刃的求解位姿与驱动弹簧状态；刀背接触 |
| 求解器 | PCG 热启动；多重网格中随状态变化的部分；线搜索与体积下限状态 |
| 表面与接触修复 | `dc_recon` 的表面重建缓存及其修复状态。若可重算，恢复后先重算再导出 |
| 时间 | step_id、native_tick、仿真时间、重力渐入相位 |
| Python 侧 | `observed`、`state`；`previous_action`（限速器）；`quality`、`grasp`、`task` 三个监视器的内部基线；`last_surface`；`_topology` 与修订号；`rng` |

### 2.4 记录与数据语义

- **分支是新回合。**
  - 生成新的 `episode_id`，另记 `parent_episode_id`、`branch_from_step`、`snapshot_sha256`、`branch_label`；
  - 分支的第一个状态就是快照状态，"N 条转移对应 N+1 个状态"照常成立；
  - 分支可以改动作、任务目标和奖励权重，不能改物理配置。物理配置一改，就不再是同一个状态。
- **质量监视器以快照状态为新基线。** 恢复后已断的边"回来了"，不能判为愈合。
- **数据读取与划分。**
  - `EpisodeReader` 不跨分支拼接窗口；
  - `splits` 把分支与父回合放进同一个重置谱系和几何组；
  - 冻结评估清单不得包含训练回合的分支。
- **同步视觉。** 启用时，恢复后用恢复出的表面重新渲染，不复用旧帧。

### 2.5 不做的

- 逐位确定的回放。
- 跨 DLL 版本或跨配置载入快照：直接拒绝。
- 肾脏场景：先做墙面与组织瓣。

### 2.6 验收

噪声参照取自 WAM 前置小测：同一 seed、同一串命令重放 5 次，ΔL 0.5–0.8 mm，偏离 ≤ 0.16 mm，起切步约 5 步。

| 编号 | 测试 | 通过条件 |
|---|---|---|
| T1 往返 | 存 → 载 → 再存 | 两份快照里"保存"类缓冲逐字节相同 |
| T2 即刻一致 | 恢复后立即导出观测 | 位置、拓扑、载荷、标记与存快照时逐位相同 |
| T3 单步冒烟 | 原轨迹与恢复轨迹各走一步相同命令 | 节点最大差 < 0.01 mm【初值】；超出时报告实测值并说明来源 |
| T4 分布等价 | 在 4 类时刻存快照：接触前、首次起切后、挤压进行中、换抓后。原轨迹与恢复轨迹各用同一串命令续跑 20 次 | 两组中位数之差不超过噪声参照：ΔL ≤ 0.8 mm、起切步 ≤ 5 步、偏离 ≤ 0.16 mm。另报 KS 检验 p 值 |
| T5 多次分叉 | 同一快照恢复 K 次，每次走不同命令，最后再恢复一次 | 最后一次恢复的状态与第一次恢复逐位相同，分支之间不互相污染 |
| T6 拓扑回退 | 切断前存快照，剪开后恢复 | 断边恢复为完好；质量检查不报愈合；之后可以照常再剪 |
| T7 准备缓存 | 缓存 `cut_ready` 快照；与重新准备各跑 20 次第一剪 | 第一剪的起切步与 ΔL 满足 T4 的条件 |
| T8 资源 | 循环存取 1000 次 | 显存与内存不持续增长；记录快照大小和存取耗时 |

**性能目标：**
- 恢复耗时：最低要求短于一次准备（11.5 s），目标 ≤ 1 s。
- 单个快照：目标 ≤ 200 MB。
- 参考：墙面牵拉有 76050 个节点，可观测状态（位置、差分速度、标记、邻接、断边分数）约 5.8 MB/步，求解器内部缓冲另计。

## 3 S16 牵拉过头的后果

### 3.1 背景

仿真器里已经有两条处于关闭状态的失败律。核函数都在 `bin-contact-groups31` 和 `bin-scissors` 两个 DLL 里，启用只需要 Python 侧传参。

| 失败律 | 机制 | 现在传入的值 |
|---|---|---|
| 撕裂律 | 伸长比超过阈值的完好边断开（`native/vendor/cuda/cut.h` 第 24–26 行，取值小于 1 即关闭；核函数 `k_TearOverstretch`）。夹持点周围 1 圈不受约束（`exempt_rings = 1`），曾被切到的切口边缘角点例外，仍受约束 | 0，即关闭（`native_backend.py` 第 304–305 行） |
| 辅助锚点断开 | 每个锚点角点的力按每子步指数平均，超过阈值就永久脱开（`xpbd/xpbd_solver.h` 第 272 行，`xpbd_solver.cu` 第 982–993 行 `k_CoreBreakCheck`）。用平均值而不是瞬时值，是为了避免普通换位误触发 | 15000 原生单位，即每个角点 150 N，实际上不会触发（`native_backend.py` 第 314–316 行） |

另外：
- 纯摩擦模式只通过了薄壁保持的正对照，GRASP-01 仍未关闭。
- 墙面牵拉默认用辅助模式。

**训练用哪条路由用户定：**
- a 撕裂律；
- b 纯摩擦滑脱；
- c 学习侧代理；
- d 锚点断开。

本节只要求仿真侧把这几条路需要的能力备好，默认效果不变。

### 3.2 S16a 撕裂律可选启用（作者）

**配置**
- 新增覆盖字段：
  - `tear_stretch_ratio`，默认 0（关闭）；
  - `tear_exempt_rings`，默认 1。
- 两者经 S17a 的覆盖机制分别进入 `CutDesc` 和 `GraspParams.exempt_rings`，并计入出处标记。

**记录**
- 每步新增的断边按原因分开：刀刃断边、撕裂断边。`LCS_GetCutDebug` 第 15 槽的累计撕裂计数可以作起点。
- 撕裂断边再按位置分三类：切口边缘、组织体内、夹持环附近。

**验证**：每个候选比值都做以下四项，比值建议先试 1.3、1.5、2.0。
1. **名义回归。** 静置、夹住保持、按原脚本三剪，都不产生撕裂断边；起切步与断边数相对关闭撕裂时无显著变化。这一项用来确认双刃起切规则不受影响。
2. **剂量扫描。**
   - 场景：墙面牵拉 `cut_ready`。
   - 方向：沿切口坐标系的 +ê_t、−ê_t、+ê_n、±ê_w。其中 ê_t = +x 指向自由端，ê_n = +y 跨切口，ê_w = ±z 出平面。
   - 剂量：0–4 mm，步长 0.5 mm，每档 10 次。
   - 记录首次撕裂的剂量与位置。
3. **重力余量。** 比值必须高于重力下的最大合法伸长，这是 `cut.h` 注释里的要求。
4. **质量检查。** 照常通过；撕裂产生的游离块按现有"超出局部范围"规则处理。

**交付：** 一张表，列出每个比值、每个方向的首次撕裂剂量，供用户决定是否采用、用哪个比值。

### 3.3 S16b 辅助锚点断开力可选启用（作者）

**配置**
- 新增覆盖字段 `grasp_core_break_force_n`，单位牛顿，默认 150（与现在一致）。
- 传入 `GraspParams.break_force` 时乘以 100，换成原生单位。

**记录**
- 每步记录脱开的锚点数、剩余夹持点数、`coreForceEMA` 的最大值和中位数。

**验证**：每个候选阈值都做以下三项。阈值建议先按现有回合里每个角点 `coreForceEMA` 的分布来选，例如名义最大值的 1.5、2、3 倍。
1. **名义回归。** 准备阶段（夹取、闭合、抬升）、剪刀换位、三剪全程都不脱开锚点。重点核对剪刀换位：以前在这一阶段见过夹持反力尖峰到 22.7 N。
2. **剂量扫描。** 设置同 S16a，记录开始脱开的剂量，以及脱开到不足以夹住的剂量。
3. **质量检查。** 照常通过；锚点脱开后组织的回弹不应触发数值异常。

**交付：** 每个阈值、每个方向的开始脱开剂量与完全脱夹剂量。

### 3.4 S16c 逐步导出拉伸、拉出量与锚点断开（作者，小）

每步记录以下几项：
- 材料边的最大伸长比，分全局、切口边缘附近、夹持环附近三个值；
- 已有的见证点保留比例、切向滑移、平均抬升，照常记录；
- 如果能分开，钳口的法向载荷与切向载荷分开记录；
- S16b 的锚点量。

这一项不改物理，只为各条路线提供可审计的依据：路线 c 选代理阈值，路线 a、d 选比值或阈值。

### 3.5 S16d 纯摩擦牵拉剂量曲线（我们做）

- **方法：** 用现有接口，`contact_model=1`，墙面牵拉 `held` 与 `cut_ready`，牵拉剂量同 S16a。
- **记录：** 夹取能否建立、滑移量、脱夹剂量。
- **前提：** 需要用户批准 GPU 时间，约 1–2 h【估算】。
- **夹取建立不了时：** 按 GRASP-01 如实记录。

## 4 S17 物理参数与几何覆盖

### 4.1 S17a 物理参数覆盖，修正出处标记（作者，小）

**覆盖结构**：在 `SceneConfig` 里新增一个冻结的覆盖结构，例如 `physics: PhysicsOverrides | None`。首批字段如下。所有范围都是建议，按数值稳定性收窄。

| 字段 | 默认 | 建议先验证的范围 | 说明 |
|---|---|---|---|
| `young_pa` | 场景值 6000 | 3000–24000 | 组织刚度。仿体可能更硬，以后按标定再扩 |
| `start_force_n` | 0.2 | 0.2–0.6 | 只开放不低于默认的值；低于 0.2 N 要用户同意（"不降门槛"） |
| `blade_friction` | 0.15 | 0.05–0.4 | 刃与组织的摩擦 |
| `grasp_friction` | 0.6（`GraspParams.friction`） | 0.3–1.2 | 只在纯摩擦模式下起作用 |
| `tear_stretch_ratio`、`tear_exempt_rings` | 0、1 | 见 S16a | |
| `grasp_core_break_force_n` | 150 | 见 S16b | |

**不开放：**
- `scissors_squeeze_cm`（2 mm 挤压规则）；
- 接触模型的内部常数；
- 迭代预算；
- 子步（已有单独的敏感性入口）。

**输入检查：** 越界或类型不对就拒绝。做法同 11-01 对材料目标 ID 的严格处理。

**出处标记修正**
- **现状：** `physical_defaults_changed` 只比较接触模型、dt、子步和网格（`training/env.py` 第 193–195 行），而且子步的基准取自 `scissors_settings()`，这个函数可能已被替换。
- **改为：** 比较 `asdict(settings)` 与导入时冻结的规范默认值，任一字段不同即为 True。
- **新增：** 上下文里加 `overridden_fields`，覆盖值计入配置哈希。
- **只读审计：** 扫描已有记录，比较 `context.settings` 与规范默认值，报告差异。我们的 `E:\datasets\可微世界模型_试采\precheck-01` 里有起切力 0.4 N、标记却为 False 的回合，可以用来核对审计结果。

**验收**
1. 单元测试：每个字段的覆盖都会改变 `settings`，并使标记为 True；不经覆盖、直接替换 `scissors_settings` 时，标记同样为 True。
2. 每个字段取范围两端，各跑一次原生准备和质量检查。
3. 不加覆盖时，保护哈希与默认结果都不变。

### 4.2 S17b 参数化几何族（作者，中）

**现状**
- 只有 wall、wall-traction、flap、kidney 四个手工场景。
- 墙面组织是 `Tab(low=(0, 0.7, 1.6), high=(2.5, 1.4, 2.0), attached=1)`（单位 cm，`scenario.py` 第 184 行），切面在 y = 1.05 cm。
- 进刀点、夹取点、抬升量都是手调常数（`WALL_BITES`、`WALL_HOLD_*`、`WALL_ORIENTATION`）。
- 只有单一几何时，分组工具返回 `has_held_out_validation=false`。

**要求**
- 墙面牵拉做成参数化族，可变参数有：沿切线的长度、高度、厚度、固定边、切面位置。切面法向仍沿坐标轴；网格间距不小于 1 mm。
- 准备脚本里的目标（夹取点、抬升、进刀点、刀程）由几何参数推导，不为每个变体手调。
- 每个变体有自己的几何哈希，`splits` 按它分组。

**验收**
1. 至少 3 个变体（其中 1 个只用于留出验证），每个各跑 5 次，都通过准备、质量检查和脚本三剪；报告起切步与完成情况，失败如实保留。
2. `splits` 在这些变体上返回 `has_held_out_validation=true`。
3. 原有场景的几何哈希与结果不变。
